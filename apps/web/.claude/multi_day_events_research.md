## 0. Owner direction 2026-10-16 (verbatim, answering the four shape questions)
**Q1 attend whole event or pick days:** "That will be decided in stages — when the event is being set up as a multi day event one of the filtering questions will be: are vendors required to be present for all days or do you accept vendors who are only available for portions of the event … if the event organizer says that the multi day event is open to vendors who can only attend for one or more of the days, but not all of the days — then we will build the capability for the app to book vendors on the days when they're available — if the event organizer says that it must be every day then obviously it has to be every day. And that may be the first version of multi day events that we build is events that are required for vendors to be present every day, and then we can add in the additional variables that allow for multiple days — you tell me if that is the best way forward or if it's better to build the more detailed variable day capability in the first version."

**Q2 fee per event or per day:** "This will also depend on the answer to question one … if it's a mandatory every-attendance event then the fee will obviously cover all the days, but if it is not … then the fee should only reflect the time that the vendor is present — we will need to prompt the event organizer when they're setting up to specify whether it is a flat rate fee and every vendor pays the same amount regardless of the time that they're there, or if the fee increases or decreases based upon the amount of time the vendor is at the event — then we will need one or more models to support that."

**Q3 ordering (separate transaction per day vs one cart with per-day pickup):** "Tell me more about the implications of each of these options so I can better understand the risks and the implications of potential changes." Owner's usage model: depends on food-truck event vs vendor event. FT: attendees mostly PRE-ORDER before the event to skip lines (choosing by reputation/offerings); inside the event they are likely to REORDER the same day, "just like they currently do for day-to-day pre-orders"; ordering tomorrow's food while at the event today is less likely, except to skip a line on day 2 after finding the item on day 1. A multi-day FT event is very likely an ALL-DAY festival (morning to evening, several days) → an attendee may order lunch AND dinner from a truck the same day; different from a one-evening event where the truck is open a few hours and the attendee picks one dinner a week ahead. → Early organizer filters after "multi-day": beginning and ending time per day on each day; that predicts same-customer-multiple-orders-per-day likelihood and may pick the ordering protocol. "We definitely do not need to build for every scenario in the first version but I think the plan should account for several versions and then we will pick the most likely versions or the versions that are easiest for us to build and offer value for multi day events while not offering every potential capability in the initial version."

**Q4 waves:** "waves and that decision is going to follow along with the decision from item 3 and the different transaction types."
